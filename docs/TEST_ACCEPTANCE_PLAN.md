# Quick_TDSNR 测试与验收方案

<!-- updated: 2026-08-31 -->

项目范围、架构和实施顺序见 [Quick_TDSNR 开发计划](DEVELOPMENT_PLAN.md)。

## 1. 测试策略

Quick_TDSNR 采用“开发与测试结合、最终验收相对独立”的模式。

正常的软件开发不宜采用“开发全部结束后，再由测试从头发现问题”的纯串行方式。尤其本项目包含复数参考阻抗、波定义、端口终接、FFT、cursor 和 Noise 组合，错误一旦进入上层 UI，定位成本很高。

本项目执行方式为：

```text
需求/公式确定
    → 先定义样例、期望值和错误边界
    → 编写单元/契约测试
    → 实现
    → 阶段集成测试
    → 阶段验收
    → 下一 Phase
    → 最终独立端到端验收
```

算法开发者可以编写单元测试，但不能只依赖自己的测试证明正确。Phase 验收和发布验收应使用独立测试清单、固定数据和未被实现代码反向生成的期望值。

## 2. 质量目标

### 2.1 正确性

- R//C、重归一化、VTF、时域和 SNR 公式符合冻结的数据契约；
- 输入 Network 不被意外修改；
- 复数频变 Zref 与 `s_def` 不匹配时拒绝计算；
- 所有端口、case、结果和文件都可追溯；
- 错误不能静默转换为零值或被排除出统计。

### 2.2 稳定性

- 单个文件/case/目标线失败不破坏其他结果；
- 取消后不生成半写入文件，已完成文件保持有效；
- UI 在长任务期间可以刷新、移动、查看日志和取消；
- 配置保存、读取和版本升级结果稳定。

### 2.3 兼容性

- 公共核心不得引入 Qt/matplotlib；
- QS 现有公共接口和测试在迁移期间保持兼容；
- Windows 安装后 PowerShell 可使用 `qts`；
- PyInstaller 环境正确加载 Qt、matplotlib、scikit-rf 和资源。

### 2.4 可用性

- 拓扑建议必须说明置信度和不确定项；
- 未确认 family1、缺失端口、case 过多等状态有明确提示；
- UI 使用简体中文，视觉、间距、按钮、分组和绘图风格与 QS 一致；
- 100%、125%、150% 显示缩放下没有关键控件遮挡或不可达。

## 3. 测试层级与责任

| 层级 | 目标 | 主要执行时机 |
|---|---|---|
| 单元测试 | 纯公式、模型、校验、边界 | 每次修改 |
| 契约测试 | Touchstone、配置 schema、manifest、公共 API | 每次公共接口修改 |
| 集成测试 | services 与 core/infra 组合 | 每个 Phase |
| QS 回归测试 | 防止公共核心抽取破坏 QS | Phase 2 起持续执行 |
| UI 组件测试 | 页面状态、按钮、校验、worker 信号 | 页面开发期间 |
| 端到端测试 | 文件→拓扑→映射→重归一化→SNR→导出 | Phase 7/8 |
| 性能与稳定性 | 长批次、内存、取消、重复运行 | Phase 5 起，Phase 8 签署 |
| 打包验收 | 安装、`qts`、资源、升级、卸载 | Phase 8 |
| 探索性测试 | 非预期组合和交互体验 | 每阶段完成前、发布前 |

建议责任划分：

- 开发者：单元、契约、组件和本阶段集成测试；
- 阶段验收者：按本文档执行固定场景，不修改期望值迁就实现；
- 发布验收者：在干净环境执行端到端、打包、性能和探索性测试。

## 4. 测试数据体系

### 4.1 合成数据

合成网络用于给出独立、可计算的期望值：

- 理想 S2P 直通、开路、短路和匹配负载；
- 多条互不耦合 p2p 通道；
- 1 驱 2 / 1 驱 3 星型 multi-drop；
- p2p + multi-drop + 孤立端口混合网络；
- 已知 Z 矩阵及可手算 Schur complement 的三端口网络；
- 等阻抗 `S21=1` 的 traveling-wave VTF；
- 频变 R//C Zref 网络；
- 人工构造 main/pre/post cursor 波形；
- 不同攻击线 Noise 已知的数组。

### 4.2 真实回归数据

从仓库 samples 中选择并固定：

- 一个典型多 Rank 原始文件；
- 一个重归一化后的 traveling-wave 文件；
- 一个含 PowerSI 端口名注释的文件；
- 一个大端口数/多频点性能样例；
- 一个已知存在拓扑歧义或孤立端口的负向样例。

真实文件只进入版本库或受控测试数据目录，不把个人绝对路径写入测试。

### 4.3 黄金结果

黄金结果必须记录：

- 生成方式和算法版本；
- 输入文件哈希；
- numpy/scikit-rf 版本；
- 关键数值及容差；
- 是否由解析公式、独立脚本或人工审核得到。

禁止用当前被测函数重新生成期望值后立即断言相等。

## 5. 通用测试标准

### 5.1 数值容差

除具体用例另有要求外：

| 类型 | 默认标准 |
|---|---|
| 解析公式/纯 numpy 小矩阵 | `rtol=1e-10, atol=1e-12` |
| 与 scikit-rf 的重归一化对比 | `rtol=1e-8, atol=1e-10` |
| Touchstone 文本写出再读取 | `rtol=1e-6, atol=1e-8` |
| CSV/JSON 标量 | 在导出精度范围内与内存结果一致 |
| 图像 | 不做像素级公式正确性判断；数值由结构化结果测试 |

若算法需要放宽容差，必须在测试中说明数值原因，不能全局放宽。

### 5.2 覆盖率

- 公共核心与 SNR 纯算法：行覆盖率不低于 90%；
- services：行覆盖率不低于 85%；
- 关键错误分支必须有显式测试；
- UI 不以总体覆盖率作为唯一门槛，六步关键流程必须有组件或端到端覆盖；
- 算法版本、配置迁移、取消、异常恢复不得依赖人工测试唯一覆盖。

### 5.3 缺陷门槛

- P0：数据破坏、安全性问题、应用无法启动；发布为 0；
- P1：核心数值错误、结果错配、主要流程不可用；阶段关闭和发布均为 0；
- P2：有绕行方式的功能/交互问题；发布前必须修复或书面接受；
- P3：轻微视觉或文案问题；记录后可进入后续版本。

### 5.4 回归与重复性

- 每次提交前运行本项目单元/集成测试；
- 公共核心修改必须运行 QS 全量 `python -m pytest tests/ -q`；
- Phase 7 起关键端到端场景连续运行 3 次，结果主键和数值一致；
- 任一偶发失败必须调查，不得简单增加重试掩盖。

## 6. Phase 1 测试：工程骨架、命令与视觉基线

### 6.1 预先建立的测试

1. 安装/开发入口：
   - editable install 后新 PowerShell 执行 `qts --version`；
   - `qts` 能创建 QApplication 并显示主窗口；
   - 无显示环境下 CLI 子命令不会误创建 GUI。
2. 分层约束：
   - 公共核心、domain、services 中扫描不到 PyQt/PySide/qtpy import；
   - 不存在模块级 `matplotlib.use(...)`。
3. UI 冒烟：
   - 主窗口、左侧 Phase 导航、中区占位页、右侧日志区存在；
   - 窗口关闭后进程退出；
   - 资源缺失时有可读错误而不是崩溃。
4. 视觉人工基线：
   - 与 QS 并排检查主按钮、GroupBox、列表、Splitter、字号和浅灰配色；
   - 100%、125%、150% 缩放截图归档。
5. 现状基线：
   - 记录 QS 全量 pytest、拓扑 20 项和时域 SNR 原型 13 项结果；
   - 记录目标机器冷启动和典型样例计算时间。

### 6.2 Phase 1 验收标准

- `qts --version` 退出码为 0，版本格式稳定；
- `qts` 从不依赖仓库当前目录的 PowerShell 中启动；
- 分层约束测试全部通过；
- 主窗口在三种缩放下无关键控件截断；
- UI 风格评审无“明显不同于 QS”的阻断意见；
- 基线报告完成，可供后续回归对比。

## 7. Phase 2 测试：公共核心抽取

### 7.1 预先建立的测试

1. 阻抗：
   - `C=0` 退化为 R；
   - R//C 解析公式；
   - 非法 R/C 和零参考阻抗。
2. 重归一化：
   - 输入 Network 不变；
   - family 覆盖完整、重复/缺失/越界拒绝；
   - 与 scikit-rf 或解析 Z→S 结果对比；
   - 非目标 family 的 Schur complement 终接验证。
3. VTF：
   - 等阻抗 `S21=1` 得到 0.5；
   - 源/负载阻抗比；
   - 复数 Zref + 非 traveling-wave 被拒绝。
4. Touchstone：
   - `QS_S_DEF`、逐频点 Zref、端口名往返；
   - 复数 power-wave 写出被拒绝；
   - 无补充注释时兼容普通文件。
5. 拓扑：
   - 现有 p2p、multi-drop、混合、孤立、断崖和 fanout 测试迁移；
   - 公共 API 不暴露 UI 私有对象。
6. 时域原语：
   - 插值/外推、梯形脉冲、FFT 卷积和 UI center 与旧实现对齐。
7. QS 兼容：
   - QS 全量 pytest；
   - 旧 import shim 的对象身份或行为保持一致。

### 7.2 Phase 2 验收标准

- 公共包可以在不安装 Qt/matplotlib 的环境导入；
- 数值容差符合 §5.1；
- QS 全量 pytest 通过；
- 公共核心覆盖率达到 90%；
- 没有一份算法在 QS 与 Quick_TDSNR 中各保留独立实现。

## 8. Phase 3 测试：文件预检、拓扑与建议映射

### 8.1 预先建立的测试

1. 文件预检：
   - 多文件同端口数/同拓扑通过；
   - 端口数、频率为空、文件损坏、端口名缺失分别提示；
   - 文件指纹变化后预检缓存失效。
2. 拓扑共识：
   - 多文件报告完全一致时为高置信；
   - 少量判据差异为中置信并列出差异；
   - 簇结构冲突为低置信并禁止自动接受。
3. S/Y/Z 判据：
   - 并行比较 S/Y/Z，不把任一种矩阵固定为默认真值；
   - 当某一判据产生不合理大簇、其他判据形成一致矩形结构时，保留分歧并选择更可信建议；
   - 用户切换判据不改变原 Network；
   - 阈值非法时被 UI 和 service 双重拒绝。
4. 建议映射：
   - 每个联通簇生成一行；
   - 同尺寸 multi-drop 生成正确 family 列数；
   - 端口名证据优先于端口号启发式；
   - 无证据时不能把 hub 静默认作 family1；
   - 孤立端口进入待处理列表。
5. UI：
   - worker 运行期间界面可重绘和取消；
   - 热力图端口编号为 1-based；
   - 高/中/低置信状态颜色、文字和 tooltip 一致。

### 8.2 Phase 3 验收标准

- 固定合成拓扑识别结果全部正确；
- 高置信建议映射端口覆盖率为 100%，且无重复；
- 中/低置信场景必须出现人工确认状态；
- 拓扑后台任务中主界面连续 2 秒无“未响应”；
- 取消请求在 2 秒内被 worker 接收并停止后续文件调度；
- 不解析 `format_report()` 文本来生成映射，必须消费结构化报告。

## 9. Phase 4 测试：映射与扫描计划

### 9.1 预先建立的测试

1. family 映射：
   - 每个端口恰好出现一次；
   - 重复、缺失、越界和空单元格；
   - 拖拽后撤销/恢复；
   - family1/source 未确认时禁止下一步。
2. 参数输入：
   - 中英文逗号和空格候选值；
   - 负数、零、NaN、Infinity、空值拒绝；
   - Cio 允许 0，不允许负数。
3. case 规划：
   - 数量等于目标 family 数乘各 R 候选轴笛卡尔积；
   - 顺序稳定、case_id 可复现；
   - 大于预设阈值时二次确认并估算文件数量。
4. 项目配置：
   - 保存/读取往返相等；
   - `schema_version` 缺失或未来版本给出明确错误；
   - 输入文件指纹变化后要求重新预检。
5. UI：
   - 建议映射预填、橙色问题单元格、统计信息和按钮状态正确。

### 9.2 Phase 4 验收标准

- 对同一配置重复规划得到完全相同的 case 顺序和 ID；
- 所有非法配置在执行前被拦截；
- 项目文件不包含个人临时绝对路径以外的不可移植运行状态；
- 配置往返测试和一次人工项目恢复测试通过；
- UI 在典型 S40P 映射表下仍可顺畅滚动和编辑。

## 10. Phase 5 测试：重归一化执行引擎

### 10.1 预先建立的测试

1. 单 case 正确性：
   - traveling-wave 输出；
   - 保留端口顺序为 source family + target family；
   - R//C Zref 与频率相关；
   - 非目标 family 终接符合 Schur complement。
2. 批处理：
   - 输入数 × case 数与计划数一致；
   - 每个输入只计算一次 Z 矩阵，可通过 spy 验证；
   - 文件重名使用稳定唯一命名；
   - 单 case 失败时后续 case 继续。
3. manifest：
   - planned/saved/failed/cancelled 数量一致；
   - 每个输出可追溯输入、family、R/C 和 kept_ports；
   - 文件路径和哈希有效。
4. 取消与磁盘异常：
   - case 边界安全取消；
   - 写盘失败不会留下可误读的半文件；
   - 磁盘不足、只读目录和非法名称产生明确错误。
5. 性能：
   - 与 Phase 1 同样例比较；
   - 检查 BLAS 线程没有明显超额订阅；
   - 连续运行后 Network 和大矩阵可释放。

### 10.2 Phase 5 验收标准

- 数值与文件往返满足 §5.1；
- 计划、成功、失败和取消计数守恒；
- 取消响应不超过当前 case 完成后的 2 秒；
- 同一基准数据的吞吐不低于 QS 当前实现的 85%；
- 无重复 S→Z 造成的数量级性能退化；
- 所有成功文件可被 scikit-rf 重读并恢复 `s_def`。

## 11. Phase 6 测试：VTF 时域与 SNR

### 11.1 预先建立的测试

1. VTF 时域：
   - 等阻抗、平坦 `S21=1` 的脉冲峰值为 0.5；
   - 频变 RC Zref 会改变波形；
   - 幅度 dB 与展开相位插值结果可复算；
   - 目标 Nyquist 超出原始带宽时产生外推提示。
2. main cursor：
   - peak 使用绝对峰值；
   - half-height-center 在平顶脉冲中心；
   - 空波形和未知方法拒绝。
3. cursor 窗口：
   - 窗内取绝对值最大点；
   - 负时间按因果零值；
   - 右侧越界必须失败，不能静默漏算 post-cursor；
   - 窗口半宽满足 `0 <= value < 0.5 UI`。
4. Noise/SNR：
   - 同一波形 cursor 绝对值线性和；
   - 不同攻击线 RSS；
   - 直通与串扰再次 RSS；
   - `SNR=Signal/TotalNoise`，零 Noise 为 Infinity；
   - 串扰复用 victim 的 cursor 时间。
5. 结果结构：
   - victim/aggressor、端口、路径、cursor 峰值完整；
   - `algorithm_version=parallel_sparam_snr_v1`；
   - 单目标线失败不污染其他目标线。

### 11.2 Phase 6 验收标准

- 现有时域 SNR 原型固定用例全部迁移并通过；
- 解析和合成样例符合 §5.1；
- 与冻结黄金文件的 Signal/Noise/SNR 在批准容差内一致；
- 所有带宽、波定义和时间窗口风险均可见；
- 公共时域原语没有与 QS 保留第二份分叉实现。

## 12. Phase 7 测试：结果工作台与端到端

### 12.1 预先建立的测试

1. 完整流水线：
   - 导入→拓扑→映射→扫描→重归一化→SNR→导出；
   - 内存传递和“保存中间 Touchstone 后重读”两条路径结果一致；
   - 结果数量等于成功 case 的 victim 数总和。
2. 导出：
   - JSON schema、CSV 列、UTF-8/UTF-8-SIG；
   - chart data 和逐攻击线 CSV 行数正确；
   - Infinity/NaN 使用明确可读表示；
   - manifest 中所有文件引用存在。
3. 结果工作台：
   - 按 file/case/family/victim/status 筛选；
   - 表格选择与波形/指标图联动；
   - 失败行不参与成功指标图，但保留错误详情；
   - 排序和筛选不改变底层结果。
4. UI 回归：
   - 六个页面前后导航保留配置；
   - 运行中禁止破坏性修改；
   - 键盘焦点、tooltip、状态颜色和简体中文检查；
   - 三种 DPI 缩放和最小窗口尺寸。
5. 重复性：
   - 同一项目连续执行 3 次，case_id、主数值和结果行关联一致。

### 12.2 Phase 7 验收标准

- 固定真实项目可无人工修改地完成端到端运行；
- 内存路径与文件路径主数值在 Touchstone 容差内一致；
- 所有结果行均可追溯到输入、case、R/C、victim 和算法版本；
- CSV/JSON 可由独立读取脚本验证；
- UI 关键流程无 P0/P1，视觉评审符合 QS 风格；
- 三次重复运行无漂移或偶发失败。

## 13. Phase 8 测试：打包、性能与发布验收

### 13.1 干净环境

至少在一台无源码路径、无开发虚拟环境的目标 Windows 机器或干净虚拟机执行：

- 全新安装；
- 新开 PowerShell 执行 `qts --version` 和 `qts`；
- GUI 图标、中文、matplotlib 图表和资源加载；
- 示例项目完整运行；
- 覆盖安装、升级、卸载；
- 卸载后用户项目和结果不被误删。

### 13.2 性能与稳定性

固定同一机器、同一数据和依赖版本，记录：

- `qts` 冷启动时间；
- 拓扑扫描时间；
- 每个重归一化 case 平均时间；
- 每个 victim 的时域/SNR 平均时间；
- 总运行时间和峰值内存；
- 取消响应时间；
- 连续运行 3 个完整项目后的资源释放。

发布阈值：

- 冷启动不超过 Phase 1 基线的 1.25 倍，且目标工作站上不超过 10 秒；
- 核心吞吐不低于对应冻结基线的 85%；
- UI 操作触发后 200 ms 内给出可见反馈；
- 长任务中 UI 不出现持续 2 秒以上的未响应；
- 取消在当前不可中断数值步骤结束后 2 秒内生效；
- 峰值内存无随 case 数量线性永久增长的泄漏趋势。

如目标硬件差异导致绝对阈值不适用，以同机基线比例为主，并记录原因。

### 13.3 发布验收场景

1. 典型高置信 multi-drop 项目，全自动建议后人工确认；
2. 拓扑冲突项目，确认不会错误自动映射；
3. 含孤立端口项目，确认执行被正确拦截；
4. 大于 500 个输出的批次，确认容量提示和取消；
5. 频变复数 Zref 项目，确认 traveling-wave 契约；
6. cursor 右侧越界项目，确认显式失败而非低估 Noise；
7. 单 case 写盘失败，确认其他 case 继续并进入 manifest；
8. 已保存项目在新版本打开，确认 schema 兼容或给出迁移提示。

## 13C. Phase 11 测试：独立 SNR 统计与二维热力图

- 主窗口为七步工作流，第六步只有频域/时域，第七步包含热力图、汇总、逐串扰和逐结果；
- 项目 current_phase 可保存和恢复到第七步，旧 schema 2 的0–5阶段值保持兼容；
- 自动忽略只有一个取值的R/Cio，只把变化参数列为热力图维度；
- 恰好两个变化维度时自动作为X/Y；超过两个时可选择X/Y并固定其余维度；
- 指标支持SNR/SNR dB、Signal、Direct/Xtalk/Total Noise；
- 三种聚合均有数值断言：SNR/Signal最好取最大、最差取最小，Noise方向相反，平均取算术平均；
- 默认聚合为最差，每个有效格点显示数值和底色，并可追溯case、结果数和代表Victim；
- 统计范围默认全部；显式选择“第六步已勾选样本”且空勾选时必须显示空结果；
- 默认工程得到16个样本、128条结果、2×4热力图且0失败；
- Quick_TDSNR全量自动化和Phase 9真实样例验收通过，P0/P1为0。

## 13A. Phase 9 测试：样本工作台与持久化缓存

### 13A.1 服务与缓存

## 15. 测试维护规则

- 修复缺陷时先增加能够复现缺陷的测试；
- 公共接口变化同步更新契约测试和接口文档；
- 算法规则变化必须升级 `algorithm_version` 并保留旧黄金结果；
- 配置结构变化必须升级 `schema_version` 并测试迁移；
- 不删除失败测试来通过阶段门；过期测试需说明需求变化和替代覆盖；
- UI 截图用于视觉评审，不代替数值断言；
- 性能测试不与普通单元测试混跑，但每个发布候选必须执行；
- 所有验收结论必须可由固定命令、固定数据和记录复现。
